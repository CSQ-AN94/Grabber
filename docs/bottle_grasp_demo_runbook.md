# 水瓶抓取 Demo 复现手册

2026-07-16 凌晨首次完整跑通：右腕视觉定位 → 锁定目标 → MoveIt 局部规划分段接近 →
低速最终接近 → 力控夹取 → 抬升 5cm → 放回桌面 → 退开。本手册记录**精确的复现步骤**
和当晚每一种失败模式的排查方法。

## 一、前置条件检查清单

| # | 条件 | 怎么确认 |
|---|------|----------|
| 1 | 瓶子放稳在桌面，周围 15cm 无遮挡 | 目视 |
| 2 | 右臂在观察位：腕部相机距瓶约 30cm，瓶子**完整**入镜、大致居中 | 起腕部直播看画面（见下） |
| 3 | 有人守硬件急停 | — |
| 4 | `table_demo` 围栏里的桌面禁入区和实际桌面一致 | 桌子挪过就必须重新标（见第四节） |
| 5 | 机器人上没有残留的 demo 进程 | `pgrep -f bottle_grasp_demo` 应为空 |

**腕部直播**（拖手臂对准瓶子时用）：
```bash
# 机器人上
python scripts/wrist_camera_server.py --host 0.0.0.0 --port 8875
# Mac 浏览器打开 http://192.168.3.68:8875
# 用完必须停掉（占用相机）：pkill -f 'wrist_camera_serve[r]'   # 注意[r]防自杀
```

画面标准：瓶子完整可见（上下都不切边）、宽度约占画面 1/5～1/4。

## 二、标准执行流程

Mac 上一键（自动同步代码+远程运行）：

```bash
scripts/run_bottle_grasp_resume.sh check   # 第1步：无运动视觉确认
scripts/run_bottle_grasp_resume.sh grasp   # 第2步：抓取+抬升+保持
scripts/run_bottle_grasp_resume.sh cycle   # 或者：抓取+抬升+放回+退开
```

`check` 通过标准：日志出现 `共识帧 7/7`、散布 <5mm。没过就调整姿态/瓶子重来，
**不要跳过 check 直接 grasp**。

执行阶段的日志节奏（正常一次 grasp 约 1.5~2 分钟）：

```
[右腕续抓定位] → 共识帧 7/7        # 完整视野下锁定抓取点（此后不再被覆盖）
[打开夹爪]
[右腕局部建图] → N 体素            # 腕部RGB-D障碍
[电子围栏离线复核] moveit_pregrasp_01 通过
[预抓取分段 1..3]                  # 每段4.5cm，段间3帧视觉复检
[预抓取复检] → "保持初始锁定目标"    # 近距漂移是伪影，忽略是正确行为
[右腕点云通道检查] 通过
[低速最后接近]                     # 检测丢失警告=夹爪遮挡，预期现象
[夹紧水瓶] → RM Plus 闭合反馈       # pos>429 才算抓到实物
[抬升 5 cm]
[放回桌面] → [松开夹爪] → [退开]    # 仅 cycle 模式
```

## 三、当晚全部失败模式排查表

| 日志报错 | 根因 | 处理 |
|---|---|---|
| `轨迹 TCP 点 N 进入禁入区 table_top` | 规划路径离桌面 <2.5cm | 正常拦截。检查起始姿态是否过低/过怪 |
| `关节 J2 距限位过近: 129.5°` | 起始姿态肘部过度折叠，直线接近无解 | 把手臂拖回标准观察位再跑 |
| `检测/深度稳定帧不足: 0/N` | 瓶子不在腕部视野/被切边/形状过滤拒绝 | 起直播看画面，重新对准 |
| `续抓目标相对保存位置跳变 >200mm` | 瓶子被大幅挪动过 | 确认瓶子位置后直接重跑（会用新定位） |
| `分段移动后目标跳变`（历史） | 近距视野截断使定位点向瓶盖漂移 | 已修：目标锁定后不再被覆盖，只警告 |
| `夹爪闭合失败`（历史，legacy API） | 位置闭合被瓶子挡住到不了目标位置 | 已修：改用 RM Plus 原生协议+抓空判定 |
| `夹爪闭合位置等同空夹` | 真的抓空了（瓶子位置错/被拿走） | 检查瓶子，重跑 |
| 蠕动式走走停停 | 密集点逐条 movej + 段间规划复检开销 | 已知现状，安全优先；后续可改轨迹透传 |

## 四、桌子挪动后：重标桌面禁入区

桌面高度是用头部相机深度+已验证的手眼外参实测的。桌子挪过后：

1. 头部相机拍深度图，取干净桌面区域像素，用 `calibration.T_base_right_to_camera_head`
   变换到右臂基座系，取 z 中位数（2026-07-15 实测 z=-0.205）
2. 改 `bottle_grasp/safety_profiles.json` → `table_demo.keepout_boxes[table_top]`：
   `max[2]` = 实测桌面 z + 0.005；前沿 `min[1]` 按桌边实际位置留 2~3cm 余量
3. 跑单测确认围栏行为：`python -m pytest test/bottle_grasp/test_algorithms.py`

## 五、已知遗留问题（影响范围与状态）

1. **MoveIt 碰撞检查完全失效**（2026-07-16 确诊）：场景里有障碍盒、防撞体已附着、
   ACM 正常，但"目标在桌子内部10cm"的规划照样瞬间成功；所有状态 validity 恒为
   valid。`is_diff` 修复（moveit_plan_once.py / moveit_validate_path.py）已提交但
   **不是根因**——嫌疑在碰撞几何/URDF/碰撞环境层面，自碰撞探针还没跑（机器人关机）。
   **当前真正的防线是我们自己的电子围栏离线复核**（每条轨迹1.5°密集插值逐点FK校验），
   当晚两次正确拦截了擦桌路径。在修好之前：**禁止依赖 MoveIt 做全局自由规划**，
   只用局部短距离规划（fence 兜底覆盖得住）。
   离线复核工具：`/tmp/fk_check.py`（机器人上，验证任意 plan json 是否违规）。
2. **"垂下→抓取→垂下"全自主循环**：被 #1 挡住。修好 MoveIt 碰撞后，
   走原有全流程（头部定位→自动选观察位→规划过去）即可，不需要示教。
3. **透明瓶深度双峰**：前壁/后壁差一个瓶径（~4.5cm）。带标签的不透明瓶无此问题。
   当晚最终 demo 用的是不透明瓶。
4. **遥操未恢复**：demo 会杀 atom/zhixing_ctrl。需要遥操时在机器人上跑官方
   `upstart_all.sh`（全量重启，含 head_servo）。
5. **头部相机自训模型对瓶子朝向敏感**：标签背对时 conf 从 0.85 掉到 0.09。
   已加 yolo11n 通用模型兜底，长期应补充训练数据。
