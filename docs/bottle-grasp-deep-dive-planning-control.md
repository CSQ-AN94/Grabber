## 1. 基础工具箱：坐标系、齐次矩阵、旋转

这一章是后面所有推导的地基。如果你对齐次矩阵已经很熟，可跳到 §1.5 的项目三偏移表。

### 1.1 位置、姿态、位姿

- **位置（position）** \(\mathbf p=[x,y,z]^T\)：一个点在哪里，三个数，单位米。
- **姿态（orientation）**：一个物体朝哪里。夹爪是水平还是竖直、从哪个方向靠近瓶子。
- **位姿（pose）= 位置 + 姿态**。SDK 用六个数表示：`[x, y, z, rx, ry, rz]`，前三是米，后三是欧拉角（弧度）。数学推导时用 \(4\times4\) 齐次矩阵。

### 1.2 旋转矩阵：为什么是 \(3\times3\) 且正交

姿态用 \(3\times3\) 旋转矩阵 \(\mathbf R\) 表示。它的三列就是"物体自身的 x、y、z 轴在世界坐标系里指向哪"：

\[
\mathbf R=\begin{bmatrix} \mathbf x_{axis} & \mathbf y_{axis} & \mathbf z_{axis}\end{bmatrix}.
\]

因为三个轴互相垂直且长度为 1，所以 \(\mathbf R\) 是**正交矩阵**：\(\mathbf R^T\mathbf R=\mathbf I\)，且 \(\mathbf R^{-1}=\mathbf R^T\)。这个性质后面会反复用到——例如"逆变换"不用真的求逆，转置即可。

`core.py::look_at_camera_pose` 就是手工构造这样一个 \(\mathbf R\)：给定相机位置和要看的目标点，先定 z 轴（指向目标），再用"世界向下"投影出 y 轴，叉乘得 x 轴。这保证相机光轴对准瓶子、图像不歪。

### 1.3 齐次矩阵：一次回答"在哪 + 朝哪"

把旋转和位移打包：

\[
\mathbf T=\begin{bmatrix}\mathbf R & \mathbf p\\ \mathbf 0^T & 1\end{bmatrix}\in\mathbb R^{4\times4}.
\]

**它最有用的性质是可以链式相乘表示坐标变换。** 若 \({}^A\mathbf T_B\) 表示"B 系在 A 系里的位姿"，则：

\[
{}^A\mathbf T_C={}^A\mathbf T_B\,{}^B\mathbf T_C.
\]

一个三维点 \(\mathbf p_C\)（在 C 系里）变到 A 系：先补一个 1 变成齐次坐标，再左乘矩阵：

\[
\begin{bmatrix}\mathbf p_A\\1\end{bmatrix}={}^A\mathbf T_C\begin{bmatrix}\mathbf p_C\\1\end{bmatrix}.
\]

代码里到处是这个模式。例如 `collision.py`：

```python
T_base_camera = robot.current_flange() @ T_flange_camera
points = (T_base_camera @ camera_points.T).T[:, :3]
```

第一行 `T_base_camera = current_flange @ T_flange_camera` 就是链式相乘 \({}^{base}\mathbf T_{camera}={}^{base}\mathbf T_{flange}\,{}^{flange}\mathbf T_{camera}\)；第二行把一堆相机系点左乘该矩阵变到基座系。

### 1.4 逆变换与"上下游"

齐次矩阵求逆有闭式解（不必数值求逆）：

\[
\mathbf T^{-1}=\begin{bmatrix}\mathbf R^T & -\mathbf R^T\mathbf p\\ \mathbf 0^T & 1\end{bmatrix}.
\]

`robot.py::current_flange` 用到它：已知 TCP 位姿，反推法兰位姿，就是右乘 \(({}^{flange}\mathbf T_{tcp})^{-1}\)。

```python
T_flange_tcp = np.eye(4); T_flange_tcp[2, 3] = self.tcp_z_m
return T_tcp @ np.linalg.inv(T_flange_tcp)
```

### 1.5 法兰、TCP、相机不是同一个点（本项目三个偏移）

```
基座 ── 七个关节 ── 法兰(flange) ── 夹爪工具中心(TCP)
                                └── 右腕 RGB-D 相机
```

- 从基座到法兰：**随关节变化**，由正运动学算。
- 从法兰到 TCP、从法兰到相机：**固定标定关系**。

| 名称 | 代码符号 | 数值 | 作用 |
| --- | --- | --- | --- |
| 腕相机外参 | `T_flange_wrist_camera` | 标定得到 | 腕相机测到的点 → 法兰 → 基座 |
| 工具偏移 | `tcp_z_m` | \(0.151\,\mathrm m\) | 法兰沿工具轴到 TCP |
| 模型-控制器法兰差 | `moveit_link7_to_controller_flange_m` | \(0.0172\,\mathrm m\) | 对齐 MoveIt 的 link7 与控制器法兰 |

**把它们混为一谈的典型后果**：规划显示安全，真实夹爪却比模型低或前 \(1.5\,\mathrm{cm}\)——刚好是某个偏移被漏乘。§4 和 §5 会看到代码在 FK/IK 前反复调用 `_set_algo_tool_z(...)` 显式指定"这次算的是到法兰还是到 TCP"，就是为了不混。

> **检查题 1.1**：`T_base_camera = current_flange @ T_flange_camera` 里，如果误用了 TCP 位姿代替法兰位姿去乘 `T_flange_camera`，点云会怎样系统性偏移？
>
> **答**：会整体沿工具轴平移约 \(0.151\,\mathrm m\)（TCP 相对法兰的偏移），所有障碍点、通道点都错位，通道检查可能漏掉真障碍或误报。

## 2. 抓取点估计：程序怎么知道该夹哪个三维点

> **本章目标**：能手推像素→基座点的变换；能对一组深度手算出稳健簇；能说清中位数/MAD/多帧共识各挡住哪种噪声。

### 2.1 为什么"检测框中心"不是抓取点

YOLO 给的是二维矩形框 \((x_1,y_1,x_2,y_2)\)。它有三个致命缺陷：

1. **没有深度**：不知道瓶子离相机多远，无法得到三维点。
2. **框含背景**：中心像素可能落在瓶子后面的桌面/墙上。
3. **夹哪里成功率不同**：夹瓶盖、瓶肩、瓶身、瓶底的稳定性差别很大。

所以本项目把"检测到瓶子"分成四个层次，只有最后一个叫抓取目标：

```
检测框
  → 可靠深度 + 抓取像素
  → 相机系三维点
  → 基座系多帧共识点   ← 只有这个才交给规划
```

### 2.2 针孔模型：从像素 + 深度到相机系三维点

相机把三维点投影到二维像素，用**针孔模型（pinhole model）**。内参 \(f_x,f_y\)（焦距，像素单位）、\(c_x,c_y\)（主点，光轴穿过图像的像素坐标）。投影是：

\[
u=\frac{f_x\,x_c}{z_c}+c_x,\qquad v=\frac{f_y\,y_c}{z_c}+c_y.
\]

我们要做的是**反投影（back-projection）**：已知像素 \((u,v)\) 和深度 \(z\)（深度相机直接给），反解三维点：

\[
\boxed{\;x_c=\frac{(u-c_x)z}{f_x},\qquad y_c=\frac{(v-c_y)z}{f_y},\qquad z_c=z.\;}
\]

**直觉**：\((u-c_x)\) 是像素离图像中心的水平偏移；除以 \(f_x\) 把"像素"换算成"每米深度对应多少米横移"的斜率；再乘真实深度 \(z\)，得到真实横向位置。

**worked example（横向）**：设 \(f_x=600\)，\(c_x=424\)，目标像素 \(u=454\)，深度 \(z=0.30\,\mathrm m\)：

\[
x_c=\frac{(454-424)\times0.30}{600}=\frac{30\times0.30}{600}=0.015\,\mathrm m.
\]

即该点在光轴右侧 \(1.5\,\mathrm{cm}\)。真实代码从 `CameraThread` 读内参，不写死。`collision.py` 里就是向量化的同一公式：

```python
(u - K[0, 2]) * z / K[0, 0],   # (u - cx) * z / fx
(v - K[1, 2]) * z / K[1, 1],   # (v - cy) * z / fy
z,
```

### 2.3 从相机系到基座系（把腕相机的运动考虑进去）

相机系点 \(\mathbf p_c\) 变到右臂基座：

\[
\begin{bmatrix}\mathbf p_{base}\\1\end{bmatrix}={}^{base}\mathbf T_{camera}\begin{bmatrix}\mathbf p_c\\1\end{bmatrix}.
\]

**头部相机**固定在身体上，外参是常数。**右腕相机**随手臂动，所以外参必须每次现算：

\[
{}^{base}\mathbf T_{wrist}={}^{base}\mathbf T_{flange}(\mathbf q)\;{}^{flange}\mathbf T_{wrist}.
\]

这正是 `demo.py` 在右腕定位时给 `perception` 的 `transform_provider`：读当前法兰位姿（由当前关节角 FK 得），再右乘固定腕相机外参。**如果这里用了旧的关节角，点就会系统性偏。**

### 2.4 深度为什么从三个区域采样

`perception.py::_zones` 从检测框里切三个子区域（瓶盖、标签、瓶身），`depth_point_for_detection` 从这三个区各随机取深度像素。目的是抗现实噪声：

| 情况 | 单点/整框中位数的风险 | 三分区采样的作用 |
| --- | --- | --- |
| 透明瓶 | 能看穿到后壁/背景，深度出现多个峰 | 多位置取样，提高命中瓶体簇的机会 |
| 标签反光 | 标签区深度失效 | 瓶盖/瓶身区仍有数据 |
| YOLO 框偏大 | 框含桌面/墙 | 后续挑"最近且被足够样本支持"的簇 |
| 单个飞点 | 一个坏值带偏平均 | 中位数 + MAD 对少量离群稳健 |

注意：**三个区域不是"取三个深度再平均"**，它们只提供候选像素池，真正的选择在下一节。

### 2.5 robust_near_cluster：从混杂深度里挑出瓶子（含手算）

把所有合法深度放进约 \(1\,\mathrm{cm}\) 宽的直方图桶，只保留"样本足够多"的连续桶，然后**从近到远**找第一个支持充足的连续簇。

**为什么选最近的簇？** 腕相机看向瓶子时，瓶前壁通常比桌面、墙、瓶后壁离相机更近；任务是夹住最靠近相机的瓶身表面，不是测到后方背景。

对选中的簇算两个稳健统计量：

\[
\operatorname{median}(z)=\text{中位数},\qquad
\operatorname{MAD}(z)=\operatorname{median}\big(|z-\operatorname{median}(z)|\big).
\]

**MAD（中位绝对偏差）** 是"离群鲁棒的散度"。当前要求 `max_depth_mad_m` \(=0.018\,\mathrm m\)，即簇内深度不能散得比 \(18\,\mathrm{mm}\) 还开。

**worked example**：抽样深度（米）：

```
0.294, 0.296, 0.295, 0.297, 0.296, 0.344, 1.82
```

- 排序后中位数 = 0.296（第 4 个）。
- 前五个（0.294–0.297）挤在一起 → 最近且支持充足的簇。
- 0.344（瓶后壁？）、1.82（背景墙）被判为离群。
- 对前五个算 MAD：中位数 0.296，各点偏差 |−0.002|,|0|,|−0.001|,|+0.001|,|0| → 偏差中位数约 \(0.001\,\mathrm m\)，远小于 \(0.018\)，通过。

对比**平均值**：\((0.294+\dots+1.82)/7\approx0.52\,\mathrm m\)——被 1.82 严重带偏，会让抓取点飞到瓶子后方半米。这就是**为什么不用平均**。

**边界情形**：若有效点不足、没有稳定簇、或 MAD 超标，程序**不拿上一帧凑合**，而是拒绝本帧、等新图像。

### 2.6 抓取像素为什么横纵向用不同规则

- 横向 \(u\)：取可信深度点的中位数（数据驱动，跟着真实瓶体走）。
- 纵向 \(v\)：**固定比例**，`grasp_height_fraction` \(=0.66\)：

\[
v=y_1+0.66\,(y_2-y_1).
\]

**为什么纵向不用深度中位数？** 有效深度像素的纵向分布随反光/标签/边缘裁切每帧漂移；若用它当抓取高度，夹点会一会儿在瓶肩、一会儿在瓶身下部。固定 0.66 是一个**显式的任务定义**："本 demo 就夹在瓶身偏下"。太高则腕相机在近距会丢目标（`core.py` 的注释明确记了这条经验）。

这不是说 0.66 对所有瓶子都对；它说明本系统把"夹哪里"当成**显式参数**，而不是让噪声隐式决定。

### 2.7 多帧共识：7 帧为什么比 1 帧可信（含几何）

`localize` 默认收 `samples=7` 帧有效三维点 \(\mathbf p_1,\dots,\mathbf p_7\)。算法：

1. 两两距离 \(d_{ij}=\lVert\mathbf p_i-\mathbf p_j\rVert_2\)。
2. 找"半径 `max_position_spread_m`\(=0.025\,\mathrm m\) 内邻居最多"的点作**种子**。
3. 要求至少 \(70\%\) 帧落在种子该半径内（7 帧至少 5 帧）。
4. 最终目标 = 内点各坐标分量的**中位数**。

**为什么不用平均？** 假设：

```
5 帧：瓶前壁，约 0.30 m
2 帧：背景/后壁，约 0.35 m
```

平均会把抓取点推到 0.31–0.32 m（两簇之间，谁也不对）；中位数共识选支持更多的前壁簇。若没有任何簇达标，正确动作是 `SafetyAbort`，不是生成"折中位置"。

### 2.8 透明瓶的先验退路（什么时候能信旧位置）

若检测框在、但本帧深度不合格，且调用方提供了已有的 base 系先验点，`localize` 可用"先验纵深 + 本帧二维框"生成临时测量。关键是**什么时候允许**：

| 场景 | 能否用先验 | 原因 |
| --- | --- | --- |
| 首次续抓定位 | 否 | 瓶/桌可能被人挪过，必须独立测量（`resume_prior_jump_m`\(=0.20\,\mathrm m\) 才是这一步的宽松跳变阈值） |
| 右腕精定位偶发透明深度失败 | 可以 | 头部粗定位已给合理纵深先验，本帧仍有二维检测 |
| 多帧都无法共识 | 否 | 视觉证据不足，不能把先验伪装成测量 |

> **检查题 2.1**：给定深度 `0.50, 0.51, 0.49, 0.50, 1.90`，`max_depth_mad_m=0.018`。哪些是内点？中位数目标深度是多少？
>
> **答**：内点是前四个（0.49–0.51），中位数 ≈ 0.50 m，MAD ≈ 0.005 m < 0.018 通过；1.90 被判离群丢弃。
>
> **检查题 2.2**：为什么横向 \(u\) 用数据中位数、纵向 \(v\) 用固定 0.66？换成两者都用中位数会怎样？
>
> **答**：横向需要贴合真实瓶体位置（数据驱动更准）；纵向需要每轮一致的夹取高度（固定比例更稳）。两者都用中位数会让抓取高度随每帧有效深度像素分布漂移，导致夹点在瓶肩/瓶身间跳变。

## 3. 路径规划：全局转移与局部接近为何分家

> **本章目标**：理解构型空间和采样式规划；能解释 7 自由度为何用采样而非解析；能追踪 `SafeMotionPlanner` 的完整审批链；能说清全局和局部两套策略各自的边界。

### 3.1 规划到底在求什么

设当前关节角 \(\mathbf q_{start}\)、目标关节角 \(\mathbf q_{goal}\)。规划器求一条连续路径

\[
\mathbf q(s),\quad s\in[0,1],\qquad \mathbf q(0)=\mathbf q_{start},\ \mathbf q(1)=\mathbf q_{goal},
\]

使**路径上每一点**都满足：

1. 不超关节限位；
2. 不与自身、左臂、桌面、场景障碍、工具保护体碰撞；
3. 对应 TCP 在电子围栏允许区、不进禁入盒；
4. 不进 \(J_4\) 奇异带（第 6 章）。

### 3.2 构型空间（C-space）：把机械臂变成一个点

**关键抽象**：机械臂有 7 个关节，它的"整个姿态"就是 7 个角度 \(\mathbf q=[q_1,\dots,q_7]\)。把这 7 个数看成一个**7 维空间里的一个点**。这个空间叫**构型空间（configuration space, C-space）**。

- 机械臂的一次运动 = C-space 里一条曲线。
- "撞桌子的所有姿态" = C-space 里一块**禁区（C-obstacle）**。
- 规划 = 在 C-space 里找一条从起点到终点、**不穿过任何禁区**的连续曲线。

**为什么这个抽象重要？** 因为障碍在真实三维世界里形状简单（一张桌子），但映射到 7 维 C-space 里的禁区形状极其复杂、无法解析写出。所以我们**不能**用"绕过一个点"这种平面几何直觉——必须在 7 维里搜索。

### 3.3 为什么用采样式规划而不是解析

在 7 维连续空间里，禁区无法写成公式。主流解法是**采样式规划（sampling-based planning）**，代表算法 RRT / PRM，MoveIt 底层用 OMPL。思路：

1. 在 C-space 里**随机撒点**（随机采样关节角组合）。
2. 对每个采样点做**碰撞检测**（用机器人+场景模型）。
3. 把无碰撞的点连成图/树，直到连通起点和终点。

它不保证最优、也不保证一定找到（概率完备），但能在有限时间处理高维复杂禁区——这是 7 自由度机械臂的现实选择。

**这就带来一个致命细节（§3.7 会详述）**：碰撞检测**只在采样点和它们的连线上离散地做**，两次检测之间是盲区。

### 3.4 为什么不能从头部检测点直接抓

头部相机适合看大范围，不适合最后夹取：距离远、视角固定、分辨率有限，夹爪接近时看不到接触区。所以全自主流程先规划到**右腕观察位**——让腕相机能以合理距离/角度/无遮挡看瓶子。

`demo.py::_observation_flange_candidates` 对每个目标生成候选相机位姿：

```
4 个观察距离 (0.30, 0.36, 0.40, 0.26 m)
× 4 个高度偏移 (0.08, 0.03, 0.13, -0.02 m)
× 3 个侧向偏移 (0.0, 0.06, -0.06 m)
= 48 个候选
```

每个候选让相机光轴对准瓶子（`look_at_camera_pose`），再右乘 \(({}^{flange}\mathbf T_{wrist})^{-1}\) 反推法兰位姿。

### 3.5 候选不是目标：观察位的三道预筛（`_observation_plan_targets`）

48 个候选先逐一过三关，才有资格交给 MoveIt：

```python
tcp = flange @ self.T_flange_tcp
self.safety.assert_tcp_point(tcp[:3, 3], ...)      # ① 电子围栏
joints = self.robot.solve_flange_ik(flange, ...)    # ② IK + 限位 + J4
score = ‖joints - current‖                          # ③ 按关节变化评分
```

- ① 围栏：TCP 必须在工作空间、允许区、不进禁入盒。
- ② IK：必须有可行逆解，且不近限位、不进 \(J_4\) 带。
- ③ 评分：离当前关节角越近分越低（越优先），减少大幅运动。

通过的候选按分数排序。**若全被拒 → `SafetyAbort`**（不硬闯）。

### 3.6 MoveIt 负责什么、不负责什么

`planner.py` 把规划请求写成 JSON（左右臂当前关节、目标关节、目标法兰、场景体素、桌面盒、工作空间、工具保护体）发给无 ROS-GUI 的 MoveIt 进程。

| MoveIt **负责** | MoveIt **不负责** |
| --- | --- |
| 大范围绕行（C-space 搜索） | 决定哪个 YOLO 框是目标 |
| 整臂自碰撞、左右臂关系 | 保证真桌子和 JSON/点云一致 |
| 检查已知场景体素/盒子 | 理解电子围栏"允许区"语义 |
| 给出关节路径 `points_deg` | 保证执行时外部环境没变 |
| | 实时腕部通道检查 |

**结论**：MoveIt 成功只代表"模型内候选路线存在"，**不等于可立即执行**。所以需要下面的独立复核。

### 3.7 采样盲区：一次真实的 narrow-band 故障（`ompl_config.py`）

OMPL 在路径**边**上按"占构型空间总尺度的比例" `longest_valid_segment_fraction` (lvsf) 离散采样做碰撞检测，**没有连续碰撞检测**。默认 lvsf = 0.01 对 7 自由度 RM75 意味着：相邻两次碰撞检测之间，关节可以走好几度、TCP 可平移近 \(10\,\mathrm{cm}\)。

**2026-07-17 真机故障**：这个盲区让规划出的路径比"垫大后的禁区盒"还深入 \(1.7\,\mathrm{cm}\)——8 个候选、16 次尝试全部在这个 narrow band 里被独立围栏拒绝，陷入死循环。

**根因与修复**：把 lvsf 从 0.01 收紧到 **0.0025**（4 倍更密），每段最大关节变化压到约 \(1.8^\circ\)，与离线复核的 `planned_joint_step_deg` \(=1.5^\circ\) 同量级——**让"规划时认为无碰"和"复核时确认无碰"的判定密度一致**。这是"规划器内部检查密度"和"外部复核密度"必须匹配的经典教训。

### 3.8 SafeMotionPlanner：一条路线的完整审批链（`safe_planner.py`）

`SafeMotionPlanner.plan` 把 MoveIt 当**候选生成器**，再用独立检查批准/否决：

```
1. 按评分取前 8 个观察位候选 (global_plan_max_candidates)
2. 每候选最多让 MoveIt 试 2 条路线 (global_plan_attempts_per_candidate)
3. 规划失败 → 换路线/换候选
4. 拿到关节路径 → interpolate_joint_path 密集插值 (≤1.5°/段)
5. 对每个密集点做 FK → TCP 点
6. 独立电子围栏逐点复核 TCP           ← 只懂 TCP，不懂整臂
7. 同一条密集路径再交 MoveIt 后验碰撞复核  ← 懂整臂，不懂围栏语义
8. 全过 → 返回 VerifiedPlan；否则有限次继续
```

两个看似重复、实则互补的复核：

| 复核 | 输入 | 关心的风险 | 盲点 |
| --- | --- | --- | --- |
| 电子围栏 | FK 出的密集 TCP 点 | TCP 越工作区/进桌面禁区/离开允许区 | 不知道手臂每一节在哪 |
| MoveIt 后验 | 同一条密集关节路径 | 整臂/工具与点云/盒子/自身/左臂碰撞 | 不带项目的允许区语义 |

**一个只盯 TCP，一个懂整臂，谁也替代不了谁。**

### 3.9 密集插值为什么必要（含算例）

`interpolate_joint_path` 让每一轴相邻变化不超过 `planned_joint_step_deg` \(=1.5^\circ\)。

**worked example**：MoveIt 给相邻两路点，某轴差 \(6^\circ\)：

\[
\text{段数}=\left\lceil\frac{6^\circ}{1.5^\circ}\right\rceil=4,
\]

拆成 4 小段，每段 \(1.5^\circ\)，各做 FK + 围栏检查。**为什么必要**：只查两个端点，端点都安全，连线中间仍可能擦过桌面。密集插值是离散近似——不能数学证明连续世界绝对安全，但配合 MoveIt 后验精确碰撞，显著缩小采样漏检。

### 3.10 违规反馈驱动的有限次重规划

若围栏发现某 TCP 点进 `table_top`，`SafeMotionPlanner` 不立刻耗尽机会，而是把该违例点变成一个 \(0.10\,\mathrm m\) (`replan_exclusion_size_m`) 的临时碰撞盒，反馈给下一次 MoveIt：

```python
feedback_boxes.append(self.safety.replan_exclusion_box(exc, ...))
```

直觉："虽然你的几何碰撞模型没认为撞了，但独立规则说这里不能走，下一条路线绕开这一小块。"

**关键是有限**：最多 8 候选 × 2 路线。**为什么不无限重试？** 因为"不断重试直到偶然找到可走路径"会掩盖现场模型错误——确定性失败比侥幸成功更安全。

### 3.11 局部接近为什么不每段都重新 MoveIt

从观察位→预抓取→抓取点，是短距离、方向明确的动作。不再让 MoveIt 对每 \(4.5\,\mathrm{cm}\)(`segment_m`) 小段全局重规划——那会造成"走一点、重算、再走一点"的蠕动，且每次可能选不易解释的路径。

局部策略（`candidate_path` + `_approach_pregrasp`）：

1. 以固定抓取姿态建预抓取点（悬停 `pregrasp_standoff_m`\(=0.085\,\mathrm m\)）和抓取点；
2. 笛卡尔直线插值出短位姿序列（`interpolate_poses`，每段 ≤ `segment_m`）；
3. 逐点电子围栏；
4. 整段连续 IK + 限位 + 跳变 + \(J_4\) 检查（`plan_ik`）；
5. 右腕深度图检查夹爪前进走廊（§5.3）；
6. 每执行段检查相机存活 + 锁定目标关联。

**所以局部不是"更简单所以更不安全"**，而是把路径形状锁成人能预测的直线，再用更贴近任务的实时感知保护它。`_approach_pregrasp` 还额外验证：距离单调收敛、终点等于悬停距离（±1.2 cm）——不收敛就 `SafetyAbort`。

> **检查题 3.1**：为什么 7 自由度机械臂用采样式规划而不是解析求一条最优路径？
>
> **答**：障碍在 7 维 C-space 里的禁区形状无法解析写出，高维连续空间的最优路径求解不可行；采样式规划用随机采样 + 碰撞检测在有限时间内找可行路径（概率完备），是现实选择。
>
> **检查题 3.2**：电子围栏复核和 MoveIt 后验复核为什么都要？各自盲点是什么？
>
> **答**：围栏只查 TCP 点的任务空间边界（不知整臂形状）；MoveIt 查整臂几何碰撞（不带允许区语义）。两者盲点互补，缺一不可。

## 4. 机械臂控制：路径怎么变成真实运动

> **本章目标**：理解 FK/IK、movej/movel 的区别与用法；能说清一次运动前的 preflight 检查链；理解夹爪状态机为什么不是简单 open/close。

### 4.1 正运动学与逆运动学

- **正运动学（FK）** \(\mathbf q\to\mathbf T_{tcp}\)：已知关节角，算末端在哪。唯一解，直接算。`robot.py::tcp_from_joints`、`controller_flange_from_joints`。
- **逆运动学（IK）** \(\mathbf T_{tcp}\to\mathbf q\)：已知想去的末端位姿，求关节怎么转。**可能有多解、也可能无解**。`robot.py::plan_ik`、`solve_flange_ik` 调 SDK 的 `rm_algo_inverse_kinematics`。

**FK 唯一、IK 多解**是本项目大量复杂度的来源：IK 多解意味着"解从一个分支跳到另一分支"会造成关节突变（§4.4 的跳变检查）；奇异点则让 IK 病态（第 6 章）。

代码在每次 FK/IK 前都调 `_set_algo_tool_z(...)` 明确"这次算到法兰还是到 TCP"：

```python
def tcp_from_joints(self, joints_deg):
    self._set_algo_tool_z(self.model_flange_offset_m + self.tcp_z_m)  # 算到 TCP
    ...
def controller_flange_from_joints(self, joints_deg):
    self._set_algo_tool_z(self.model_flange_offset_m)                 # 算到法兰
    ...
```

### 4.2 RobotSession：SDK 的安全包装

`demo.py` 不直接调 `rm_movej`/`rm_movel`，而是走 `RobotSession`，让每次执行都统一走状态检查、错误包装、停止行为、工具坐标设置：

```
BottleDemo → RobotSession → Realman SDK → 控制器与电机
```

这条封装边界让"规划逻辑"不必知道 SDK 返回码细节，也避免不同代码路径绕过安全检查。

### 4.3 movej 与 movel

| 指令 | 给控制器的目标 | 典型用途 | 直觉 |
| --- | --- | --- | --- |
| `movej` | 七个关节角 | 执行 MoveIt 全局路径；\(J_4\) 弯肘逃逸 | 让每个关节转到指定角度 |
| `movel` | TCP 位姿 | 预抓取接近、最后接近、抬升、下降、退开 | 让末端沿笛卡尔**直线**移动 |

- 全局路径本就是关节路径 → `execute_planned_joints` 先密集插值（`_dense_joint_path`），再逐个 `movej`。这样每段 SDK 关节运动与已检查路径尽量接近。
- 局部段先在笛卡尔空间定"末端怎么直线走"，`plan_ik` 逐点确认有可行关节解，再 `movel`。

### 4.4 plan_ik 里的四道门禁（控制层的核心）

`plan_ik` 对一串目标位姿逐点求 IK，每点过四关（`robot.py:349`）：

```python
if rc != 0: raise ...                                     # ① IK 有解吗
if not (lo+margin ≤ angle ≤ hi-margin): raise ...          # ② 距限位 ≥3°
if abs(solution[3]) < j4_singularity_deg: raise ...        # ③ J4 不进奇异带(<8°)
if max(|solution - q|) > 28: raise ...                     # ④ 相邻解跳变 ≤28°
```

| 门禁 | 防什么 |
| --- | --- |
| ① 有解 | 目标不可达 |
| ② 限位余量 `joint_limit_margin_deg=3°` | 贴机械/软件边界运行 |
| ③ \(J_4\) 奇异带 `j4_singularity_deg=8°` | 接近伸直肘时的病态笛卡尔控制（第 6 章） |
| ④ 跳变 ≤28° | IK 从一个分支突跳到另一支，造成大幅急动 |

`allow_first_jump` 只在"第一点相对当前姿态"允许大跳（因为局部段起点可能就该有一次大转），后续点仍严格。

### 4.5 一次运动前检查什么（preflight）

真机 `execute` 前 `_preflight` 检查（`robot.py::assert_arm_healthy` 等）：

1. 右臂控制器与全部 7 关节使能、错误码正常（`rm_get_arm_all_state` 的 `joint_en_flag`/`joint_err_code`）；
2. 是否仅出现**可恢复的瞬态通信丢帧**（0xF000），复读两次已恢复才放行（`recover_transient_joint_frame_loss`）；
3. SDK 报告的当前 TCP 可读；
4. 控制器**原生**电子围栏是否意外仍启用——若启用则**中止而非擅自关闭**（可能是现场另一安全系统的配置，本 demo 的 Python 围栏无权覆盖）；
5. RM Plus 夹爪使能、无系统/自由度错误。

**为什么 `assert_arm_healthy` 要读 `rm_get_arm_all_state` 而不只看汇总状态？** 代码注释记录了真实教训：汇总 `err=0` 时，单关节仍可能带 live 错误（真实 J7 0xF000 让每条运动指令返回 API2 -6）。汇总状态会骗人，必须看每关节。

### 4.6 执行中如何停止：停住并保持，不自动撤退

`scripts/bottle_grasp_demo.py` 为 Ctrl+C / SIGTERM 注册停止事件；`move_linear`、`execute_planned_joints` 每次发指令前检查它。异常或用户停止时，外层 `finally` 调 `RobotSession.hold`（`rm_set_arm_slow_stop` 慢停）。

**设计选择是"停止并保持"而非自动撤退**：

```
未知错误 → 此刻不能可靠相信周围空间 → 后退会引入新的未验证运动
        → 保持不动，由现场人员观察处置
```

`movel` 失败时 `_motion_failure_context` 在断开 SDK 前抓一份快照（关节、控制器、碰撞级别、围栏状态……）；特别区分 rc == -6（外部停止指令，**不是**点云障碍或 Python 围栏拒绝），避免误诊。

### 4.7 夹爪不是简单 open/close（RM Plus 状态机）

本机是 RM Plus（ZX）夹爪，**旧 `rm_set_gripper_*` API 控不了它**，必须用 `rm_get_rm_plus_state_info` 读状态。每轮抓取的夹爪流程：

```
观察位自由空间
  → 空夹标定：实测今天的空夹闭合位 baseline (calibrate_empty_close)
  → 打开
  → 接近水瓶
  → 带力闭合 (gripper_force=30)
  → 连续读 pos/speed/dof_state
  → 与本轮空夹 baseline 比较，判定是否抓到实物
```

**为什么要每轮实测空夹基线？** 2026-07-15 真机：写死的空夹常量会随环境/夹爪状态漂移，导致把真实抓取成功误判成空夹。所以 `calibrate_empty_close` 在夹爪前方无物体时实测 baseline，`close_gripper` 判定：

\[
\text{抓到} \iff \text{dof\_state}=3\ \text{且}\ \text{pos} > \text{baseline}+\underbrace{6}_{\text{gripper\_object\_margin}}.
\]

余量取 6 的教训：2026-07-15 实测抓稳的窄金属瓶只比空夹基线高 8，旧余量 35 把真实成功误判成空夹。

**`_command_gripper_position` 的状态机细节**（`robot.py:672`）也值得学：RM Plus 换向时会发一帧内部不一致的瞬态（state=5/6 但 sys_state=0），代码不把单帧运动样本当终态——要求"停住的故障连续 3 帧"才判故障，"稳定终态（state∈{2,3} 且 speed=0）连续 3 帧"才判完成。这是**去抖动（debounce）**，防止瞬态误判。

> **检查题 4.1**：为什么全局路径用 `movej`、局部接近用 `movel`？
>
> **答**：全局路径本就是 MoveIt 给的关节路径，`movej` 直接执行关节角，最贴合已检查路径；局部接近要求末端走人可预测的笛卡尔直线，`movel` 让 TCP 沿直线移动。
>
> **检查题 4.2**：`assert_arm_healthy` 为什么不能只看汇总 `err=0`？
>
> **答**：汇总状态可能 `err=0` 而单关节仍带 live 错误（如 J7 0xF000），会让每条运动指令失败；必须逐关节读 `joint_err_code`。

## 5. 避障：三个尺度、三层检查

> **本章目标**：理解为什么"避障"不是一个函数而是三层；能手算圆柱通道判定；能说清桌面自适应的四条保守规则。

"避障"是三个不同尺度的问题，本项目用三层各管一段，盲点互补。

### 5.1 第一层：MoveIt 整臂碰撞 + 场景体素（`scene.py`）

MoveIt 看到：右臂+左臂模型、自碰撞规则、头部 RGB-D 转的场景体素、safety profile 的桌面盒、工具保护体。

`scene.py::build_scene_voxels` 做几件关键事：

1. 把深度图按稀疏网格反投影为 base 系点云；
2. **移除水瓶检测框附近的点**（否则把目标瓶当"不可接近障碍"）；
3. **移除图像下方**易看到机器人自身的区域（`scene_image_bottom_crop=405`，否则把自己投回世界当障碍）；
4. 只保留瓶子附近一定工作范围的点；
5. 以 `scene_voxel_m`\(=0.065\,\mathrm m\) 体素去重，最多保留 `scene_max_voxels=550` 个。

**体素是近似**："这个 \(6.5\,\mathrm{cm}\) 小立方体里有障碍"，牺牲几何精度换规划在有限时间完成。

### 5.2 第二层：电子围栏（`safety.py`）——纯几何盒子判定

`SafetyProfile.assert_tcp_point` 对每个 TCP 点按顺序判断：

```
① 必须在总工作空间内（含 clearance 内缩）
② 不能进任何禁入盒（含 clearance 外扩）
③ 必须落在至少一个允许区
```

盒子包含判定就是逐轴比较（`FenceBox.contains` / `contains_expanded`）：

\[
\text{point} \in \text{box} \iff \bigwedge_{i\in\{x,y,z\}} \big(\min_i+m \le p_i \le \max_i - m\big),
\]

其中 \(m\) = `clearance_m` \(=0.025\,\mathrm m\)。三类元素语义不同：

| 元素 | 例子 | 作用 | margin 方向 |
| --- | --- | --- | --- |
| 总工作空间 | 右臂最大长方体 | 防止远离已验证操作区 | **内缩**（越靠边越危险） |
| 禁入盒 | `table_top` | 明确禁止 TCP 穿入 | **外扩**（离桌面太近也拒） |
| 允许区 | 桌面上方任务体积、示教通行包络 | 不让 TCP 飞到未验证的地方 | 不缩（见下） |

**为什么允许区不各自内缩？** 代码注释（`safety.py:125`）：允许区是"已经安全的走廊"，各自内缩会在两个有效走廊的重叠处切出人为空隙。clearance 已经由外层工作空间和外扩禁入盒保证。

**很重要的限制**：**电子围栏只检查 TCP 点，不知道手臂每一节在哪。** 这正是它必须和 MoveIt 整臂碰撞并用的原因（§3.8）。

**给 MoveIt 的盒子还要额外垫大**（`moveit_collision_boxes`，注释 `safety.py:145`）：因为 MoveIt 只做几何碰撞、不知道围栏还要 clearance；给它精确盒子它会规划出"贴着盒面飞"的路径，随后被离线围栏否决。所以四个水平侧面 + 顶面各外扩 `clearance_m + 0.02` = \(4.5\,\mathrm{cm}\)。这个数值 + 更密的 lvsf 的组合是 2026-07-18 的调整，注释明确写"还没真机验证过，下次连机必须先跑多轮确认不回到 narrow-band 拒绝循环"。

### 5.3 第三层：右腕点云"最后接近通道"（`collision.py`，含手算）

全局 MoveIt 点云来自头部相机；最后接近时最关心的是**夹爪正前方当前有没有突然出现障碍**。`check_approach_corridor` 从右腕深度图构点云，删掉水瓶检测框附近像素（`±8` 像素带），然后做一个**圆柱通道**检查。

设 TCP 当前点 \(\mathbf s\)、锁定目标 \(\mathbf t\)、任意点云点 \(\mathbf p\)。先求 \(\mathbf p\) 在线段 \(\mathbf{st}\) 上的**投影比例**（clamp 到 [0,1]）：

\[
a=\operatorname{clip}\!\left(\frac{(\mathbf p-\mathbf s)^T(\mathbf t-\mathbf s)}{\lVert\mathbf t-\mathbf s\rVert^2},\,0,\,1\right).
\]

线段上离 \(\mathbf p\) 最近的点：\(\mathbf c=\mathbf s+a(\mathbf t-\mathbf s)\)。若**垂直距离** \(\lVert\mathbf p-\mathbf c\rVert <\) `corridor_radius_m`\(=0.045\,\mathrm m\)，且 \(0.08<a<0.86\)（不算起点/终点附近），就是走廊里的可疑点。可疑点 ≥ `obstacle_min_points`\(=18\) 则 `SafetyAbort`。

**worked example**：\(\mathbf s=(0,0,0)\)，\(\mathbf t=(0.20,0,0)\)（正前方 20 cm），障碍点 \(\mathbf p=(0.10,0.03,0)\)：

- \(\mathbf t-\mathbf s=(0.20,0,0)\)，\(\lVert\mathbf t-\mathbf s\rVert^2=0.04\)。
- \(a=\dfrac{(0.10)(0.20)+0+0}{0.04}=\dfrac{0.02}{0.04}=0.5\)（在 0.08–0.86 内，算）。
- \(\mathbf c=(0.10,0,0)\)，垂直距离 \(=\lVert(0,0.03,0)\rVert=0.03\,\mathrm m<0.045\) → **可疑点**。

若这样的点 ≥ 18 个，说明夹爪直线冲向瓶子的路上有物体挡着，中止。

**这层解决的不是全臂碰撞，而是"直线冲向瓶子时前方有没有额外物体"。**

### 5.4 桌面为什么每轮拟合（`table_model.py`，四条保守规则）

`fit_table_top` 从头部点云在水瓶下方一定范围找"支持点最多的水平平面"。它**不无条件改围栏**：

1. 找不到足够点支持的平面（内点 < `table_fit_min_inliers=60`）→ 直接中止；
2. 实测桌面高度与 profile 差超过 `table_fit_height_tolerance_m`\(=0.12\,\mathrm m\) → 直接中止（布置真的变了，走 runbook 重测）；
3. 在容忍范围内，禁入盒顶面才跟随实测桌面（自适应）；
4. 水平范围**只允许扩张，不允许因为相机没看见而缩小**。

**第 4 条最保守**：相机看不到桌边不代表桌子不存在；缩小禁入盒会把"没测量"误当"安全空间"。

### 5.5 三层协同：一个未建模杯子的案例

| 检查时机 | 最可能发现它的层 | 结果 |
| --- | --- | --- |
| 头部视野清楚，去观察位前 | 第一层：MoveIt 体素碰撞 | 尝试绕行或换观察位 |
| 路线采样太粗，TCP 靠桌边 | 第二层：独立电子围栏 | 拒绝 TCP 点，违例反馈成临时盒重规划 |
| 杯子刚被放到夹爪正前方 | 第三层：右腕通道点云 | 最后接近前中止 |
| 杯子完全不在任意相机视野 | 三层都可能漏 | 必须靠现场清场 + 人员急停 |

**没有任何一层能声称"我解决了全部障碍"。叠加它们，是因为各自盲点不同。**

> **检查题 5.1**：TCP 在 \(\mathbf s=(0,0,0)\)，目标 \(\mathbf t=(0,0.30,0)\)，点云点 \(\mathbf p=(0.02,0.15,0)\)，`corridor_radius_m=0.045`。它算走廊障碍吗？
>
> **答**：\(a=\dfrac{0\cdot0+0.15\cdot0.30+0}{0.09}=0.5\)（在范围内）；\(\mathbf c=(0,0.15,0)\)，垂直距离 = 0.02 m < 0.045 → 是可疑点（够 18 个才中止）。
>
> **检查题 5.2**：桌面拟合为什么"只许扩不许缩"？
>
> **答**：相机看不到桌边不等于桌边不存在；缩小禁入盒会把未测量区域误当安全空间，可能让 TCP 撞进真实桌面。

## 6. 奇异点（上）：从雅可比推导，到 \(J_4\approx 0\) 为何危险

> **本章目标**：这是你最不满意的一章。我们不再只给"\(|q_4|<8^\circ\) 就拒"的工程门禁，而是从雅可比矩阵一步步推出奇异的数学含义，用肩-腕几何解释 \(J_4\) 为什么特殊，并**证明**绕工具轴 roll 改不了 \(|J_4|\)。

### 6.1 速度层的桥梁：雅可比矩阵

FK 是位置层的映射 \(\mathbf q\to\mathbf x\)（\(\mathbf x\) 是 TCP 位姿，6 维：3 平移 + 3 旋转）。对时间求导，得到**速度层**的线性关系：

\[
\boxed{\;\dot{\mathbf x}=\mathbf J(\mathbf q)\,\dot{\mathbf q}\;}
\]

- \(\dot{\mathbf x}\in\mathbb R^6\)：TCP 的线速度 + 角速度。
- \(\dot{\mathbf q}\in\mathbb R^7\)：七个关节的角速度。
- \(\mathbf J(\mathbf q)\in\mathbb R^{6\times7}\)：**雅可比矩阵**，把关节速度线性映射成末端速度。它的每一列表示"第 \(i\) 个关节单独转动时，末端会怎么动"。

**直觉**：雅可比是"当前姿态下，关节动作和末端动作之间的汇率表"。汇率好的时候（\(\mathbf J\) 满秩、条件数小），小关节动作换来可控的小末端动作；汇率差的时候（接近奇异），要末端动一点点可能需要关节疯狂转。

### 6.2 奇异点的精确定义

**奇异点（singularity）**：使 \(\mathbf J(\mathbf q)\) **降秩**（rank deficient）的关节姿态 \(\mathbf q\)。

降秩意味着什么？\(\mathbf J\) 的列张成的空间（能实现的末端速度方向）**塌缩了一个维度**。后果有两面：

1. **某些末端方向无法由小关节动作实现**——那个方向"丢了"。
2. **要在残存方向上得到一个普通末端速度，可能需要极大的关节速度**——因为汇率趋于无穷。

用**奇异值**说更精确：对 \(\mathbf J\) 做奇异值分解 \(\mathbf J=\mathbf U\boldsymbol\Sigma\mathbf V^T\)，奇异值 \(\sigma_1\ge\dots\ge\sigma_6\ge0\)。**条件数** \(\kappa=\sigma_1/\sigma_6\)。奇异点处 \(\sigma_6\to0\)，\(\kappa\to\infty\)。IK 里要求的关节速度大致按 \(1/\sigma_6\) 放大——所以接近奇异时关节速度爆炸。

**可操作度（manipulability）** \(w=\sqrt{\det(\mathbf J\mathbf J^T)}=\sigma_1\sigma_2\cdots\sigma_6\)，奇异点处 \(w\to0\)。它是"这个姿态离奇异有多远"的一个标量指标。

### 6.3 为什么控制会"病态"：一个 2 连杆直观模型

7 自由度太复杂，先看最简单的**平面 2 连杆**看清本质。连杆长 \(l_1,l_2\)，关节角 \(\theta_1,\theta_2\)。末端位置：

\[
x=l_1\cos\theta_1+l_2\cos(\theta_1+\theta_2),\quad
y=l_1\sin\theta_1+l_2\sin(\theta_1+\theta_2).
\]

雅可比（2×2）的行列式可化简为：

\[
\det\mathbf J=l_1 l_2\sin\theta_2.
\]

**关键结论**：当 \(\theta_2=0\)（手臂**完全伸直**）或 \(\theta_2=\pi\)（完全折叠）时，\(\sin\theta_2=0\)，\(\det\mathbf J=0\)——**奇异！**

伸直时的物理含义：末端在"沿手臂方向"上已经到达最远，想让它**继续沿这个方向外移**，任何关节小转动都做不到（一阶失效）；想让它**横向移动**又需要肘部突然决定往哪边弯。数学解可能存在，实际控制却剧烈跳变。

**这就是 \(J_4\approx0\) 危险的本质**：对 7 自由度机械臂，\(J_4\)（第 4 关节，肘）就扮演 2 连杆里 \(\theta_2\) 的角色——它控制手臂"伸直/弯曲"的程度。\(J_4\approx0\) ≈ 肘部接近完全伸直 ≈ \(\sin\theta_2\approx0\) ≈ 雅可比接近降秩。

### 6.4 肩-腕距离：为什么 \(|J_4|\) 由几何唯一决定

把 7 自由度手臂抽象成"肩 — 上臂 — 肘 — 前臂 — 腕心"。上臂长 \(a\)、前臂长 \(b\) 固定。肘角（本质由 \(J_4\) 主导）决定了**肩到腕心的直线距离** \(d\)。用余弦定理：

\[
d^2=a^2+b^2-2ab\cos(\pi-\text{elbow})\;\Longrightarrow\; d\ \text{与肘角一一对应}.
\]

反过来：**给定腕心位置，肩到腕心的距离 \(d\) 就定了，于是肘角、也就是 \(|J_4|\) 被唯一确定**（在一个分支内）。

- \(d\) 接近 \(a+b\)（腕心离肩最远）→ 手臂几乎伸直 → 肘角 → 0 → \(J_4\to0\) → **奇异**。

这条几何事实是理解两种逃逸策略的钥匙，下一节展开。

### 6.5 证明：绕工具 z 轴 roll 改不了 \(|J_4|\)

**命题**：保持 TCP 位置不变、只绕工具自身 z 轴旋转（roll）末端姿态，无法把 \(|J_4|\) 从接近 0 变成安全角度。

**证明思路**：
- 腕心（wrist center）到肩的距离 \(d\) 只取决于**腕心位置**，而腕心位置由 TCP 位置和"从腕心到 TCP 的固定偏移方向"决定。
- 绕工具 z 轴 roll 改变的是末端**朝向**（以及 IK 落在哪个分支），但对一个典型腕部构型，它**不移动腕心**（腕心在工具 z 轴上或其固定偏移处，绕该轴转不改变腕心位置）。
- 腕心不动 → \(d\) 不变 → 由 §6.4，肘角（\(|J_4|\)）不变。∎

**所以**：如果当前肘部本来就几乎伸直，任何"保持 TCP 位姿的 roll"都救不了 \(J_4\)。这解释了 2026-07-17 真机 finish 阶段的故障——所有 roll 重试被耗尽却仍在奇异带。要离开奇异带，**必须移动腕心**：要么改变目标位置/底盘（让 \(d\) 变小），要么在关节空间直接弯肘（§7.2）。

### 6.6 本项目为什么用工程门禁而不是通用条件数分析

项目**不**对完整 7×6 雅可比做通用 SVD/条件数分析，而是用一个已验证的工程门禁：

\[
|q_4| < 8^\circ\ (\text{`j4\_singularity\_deg`}) \ \Longrightarrow\ \text{拒绝}.
\]

**为什么这样够用、且更好？**

| 维度 | 通用条件数分析 | 本项目 \(J_4\) 门禁 |
| --- | --- | --- |
| 普适性 | 覆盖所有类型奇异（腕、肩、肘） | 只针对本机构最常遇到的肘奇异 |
| 可解释性 | \(\kappa>阈值\) 难对应到操作动作 | "肘快伸直了" 现场一看就懂 |
| 参数标定 | 阈值随姿态/任务漂移，难定 | \(8^\circ\) 是本机构+本任务实测的保守带 |
| 计算 | 每点 SVD | 每点看一个关节角，极廉价 |

这不是"宇宙中所有 \(J_4=0\) 都不可动"的数学定理，而是**此 Realman 机构、此任务、此控制方法下的安全工作区约束**。简单、可解释，直接进 `plan_ik` 的每个路径点。

配套的两个门禁（§4.4）分工：

| 门禁 | 防的是 |
| --- | --- |
| \(J_4\) 奇异带 (<8°) | 接近伸直肘的病态笛卡尔控制 |
| 关节限位余量 (≥3°) | 贴机械/软件边界运行 |
| 连续解跳变 (≤28°) | IK 从一个分支突跳到另一支 |

> **检查题 6.1**：2 连杆机械臂 \(\det\mathbf J=l_1l_2\sin\theta_2\)。\(\theta_2=180^\circ\) 时奇异吗？物理上是什么姿态？
>
> **答**：\(\sin180^\circ=0\)，奇异。物理上是手臂完全折叠（前臂叠回上臂），腕心到肩距离最小，也是边界。
>
> **检查题 6.2**：为什么绕工具轴 roll 救不了接近伸直的肘？
>
> **答**：roll 不移动腕心，腕心到肩距离 \(d\) 不变，由几何 \(d\) 唯一决定肘角，故 \(|J_4|\) 不变。要改变肘角必须移动腕心。

## 7. 奇异点（下）：两种失败必须分开，两种逃逸各管一段

> **本章目标**：把"目标会进奇异带"和"起点已在奇异带"两种情形彻底分开；逐行读懂两种逃逸代码；掌握真机故障的诊断顺序。

### 7.1 两种"奇异问题"必须分开（理解源码最关键的一点）

| 情况 | 发生在哪 | 代码正确处理 | 对应函数 |
| --- | --- | --- | --- |
| **目标/路径点会落入 \(J_4\) 带** | 规划一个新局部位姿时 | 绕工具接近轴转小角度，重做 IK | `_plan_ik_avoiding_singularity` |
| **当前起点已在 \(J_4\) 带** | 要开始抬升/下降/退开等局部笛卡尔动作前 | 先在关节空间**只弯 \(J_4\)** 逃逸，再从新 TCP 重建路径 | `escape_j4_singularity` |

**为什么不能两种都用"旋转夹爪"？** 见 §6.5 的证明：roll 改变末端朝向和 IK 分支，但不移动腕心、不改变肩-腕距离。若当前肘本来几乎伸直，保持 TCP 位姿的 roll 无法把 \(q_4\) 从接近 0 变成安全角。**roll 能解决的是"分支/限位/跳变"类拒绝，不是"几何伸直"类拒绝。**

### 7.2 方法一：绕接近轴的小角度重试（目标会进带时）

`demo.py::_plan_ik_avoiding_singularity` 对局部路径依次尝试：

\[
0^\circ,\ +8^\circ,\ -8^\circ,\ +15^\circ,\ -15^\circ,\ +25^\circ,\ -25^\circ.
\]

对每个路径位姿，右乘绕工具 z 轴的旋转矩阵，再做完整 `plan_ik`：

```python
for roll_deg in (0, 8, -8, 15, -15, 25, -25):
    if roll_deg:
        roll = Rotation.from_euler("z", roll_deg, degrees=True).as_matrix()
        rotated = [ pose with T[:3,:3] = T[:3,:3] @ roll for pose in poses ]
    else:
        rotated = list(poses)
    try:
        self.robot.plan_ik(rotated, params, allow_first_jump=...)
        return rotated          # 关键：返回真正被执行的、旋转后的姿态
    except SafetyAbort:
        continue                # 换下一个角度
```

**关键实现细节**：返回值 `rotated` 替换调用方原来的 `poses`——因为真正被执行的姿态必须和通过逆解检查的姿态**一致**，不能"检查转过的、执行没转的"。

`candidate_path`（建抓取/预抓取姿态时）也尝试 \(0^\circ,\pm15^\circ,\pm30^\circ\)。这些角度**不改变瓶子位置**，只让夹爪在不改接近位置的前提下换一个可行的姿态/IK 分支。

**何时有效？** 原姿态近关节限位、某分支不连续、或略改手腕方向就能让 IK 离开危险带时。

**何时无效？** 目标太远、手臂近乎完全伸直——无论怎么绕自身轴，肘部几何仍在奇异带。此时 `_plan_ik_avoiding_singularity` 抛出的错误信息明确提示："需要调整目标高度/距离或移动底盘"。

### 7.3 方法二：\(J_4\) 弯肘逃逸（起点已在带内时）

`robot.py::escape_j4_singularity` **只在当前 \(|q_4|<8^\circ\) 时运行**。它把 \(J_4\) 移到 \(\pm14^\circ\)（`j4_escape_deg`，比奇异带宽出 6°，避免逃逸后又贴带边被拒），逐点校验后 `movej` 执行：

```python
q = self.joints_deg()
if abs(q[3]) >= params.j4_singularity_deg:
    return None                                  # 不在带内，无需逃逸
preferred = 1.0 if q[3] >= 0 else -1.0           # 优先往当前符号方向弯
for sign in (preferred, -preferred):             # 两个方向都试
    target = list(q); target[3] = sign * params.j4_escape_deg
    if not (lo <= target[3] <= hi):              # ① 目标 J4 仍留限位余量?
        continue
    dense = interpolate_joint_path(q, [target], planned_joint_step_deg)  # ② 1.5°插密
    for joints in dense:                         # ③ 每个插值点 FK
        tcp = self.tcp_from_joints(joints)
        safety_profile.assert_tcp_point(tcp[:3, 3], ...)                 # ④ 逐点围栏
    self.execute_planned_joints([target], ...)   # ⑤ 全过才 movej 执行
    return target                                # ⑥ 返回逃逸后关节角
raise SafetyAbort("两个弯肘方向均不可行")
```

**为什么弯肘逃逸对控制器是安全的，而在带内做笛卡尔直线不安全？**（`escape_j4_singularity` 的 docstring 讲透了）：

- 危险的是"在奇异带内做**笛卡尔**运动"——因为要经过病态雅可比（\(\dot{\mathbf q}=\mathbf J^{-1}\dot{\mathbf x}\) 里 \(\mathbf J\) 接近奇异，关节速度爆炸）。
- 而**纯关节运动**（`movej`）**不经过雅可比求逆**——直接给关节角，控制器插值关节即可。所以穿越/离开奇异带对纯关节运动是干净的。

**为什么逃逸后必须重建路径？** 因为改变 \(J_4\) 会让 TCP 实际位置变化。若仍执行逃逸前算好的"向上抬 5 cm"位姿序列，就等于从错误起点执行路径。

### 7.4 两种方法怎样在 `_plan_local_leg` 里组合

`demo.py::_plan_local_leg` 是抬升/下降/退开的统一入口，它先逃逸、再规划：

```python
def _plan_local_leg(self, name, build_path, params, *, allow_first_jump=False):
    escaped = self.robot.escape_j4_singularity(params, self.safety)  # ① 起点在带内?先弯肘
    if escaped is not None:
        self.stage("J4 奇异带弯肘逃逸", ...)
    return self._plan_ik_avoiding_singularity(                       # ② 再对新路径做roll重试
        build_path(),                                               #    build_path 在逃逸后才调用!
        params, allow_first_jump=allow_first_jump,
    )
```

**为什么收的是 `build_path` 回调而不是现成路径？**（这是设计精髓）逃逸会移动 TCP，所以路径必须在逃逸**之后**、从**新姿态**构建。若先把路径算好再传进来，逃逸后这条路径的起点就错了。回调把"构建路径"这个动作延迟到逃逸完成之后。

组合逻辑一句话：**先用关节空间弯肘把起点带离奇异带（方法二），再用绕轴 roll 处理新路径里可能的分支/限位类奇异（方法一）。** 两者顺序不能反。

### 7.5 奇异失败的实际诊断顺序

看到 `路径点 N J4=X°，进入奇异区` 时，**不要先把阈值从 8° 改小**。按顺序判断：

1. 当前观察位是否太远、太低、太接近手臂最大伸展？（→ \(d\) 太大，几何奇异）
2. 目标瓶子是否移动，或手眼标定是否让目标误落到远处？
3. 绕接近轴的候选（\(0,\pm8,\pm15,\pm25\)）是否已全部尝试？
4. 若是放回/抬升/退开，起点是否已在带内、是否需要执行弯肘逃逸？
5. 是否应调整底盘位置或重新选观察位，而不是强迫手臂穿过带？

**把阈值调小只是允许更接近病态区域运行；它不修复"几何不可达"。** 阈值不是问题的解，几何才是。

### 7.6 把奇异处理连起来：一次 finish 阶段的推演

假设机器人已抓到瓶、要抬升 5 cm，但当前姿态 \(q_4=3^\circ\)（在带内）：

```
_plan_local_leg("抬升", build_lift_path, ...)
  → escape_j4_singularity: |3°|<8° → 弯肘到 14°
      · 优先 +1 方向（当前 q4=3>0）→ target[3]=+14°
      · 检查 +14° 距限位 ≥3°  ✓
      · q4: 3°→14° 按 1.5° 插成约 8 个点
      · 每点 FK→TCP→逐点围栏  ✓
      · movej 执行，TCP 已改变
      · 返回 escaped, stage("J4 奇异带弯肘逃逸: 已弯肘至 J4=14.0° 后重建路径")
  → build_lift_path()   ← 现在才从"逃逸后的新 TCP"构建抬升路径
  → _plan_ik_avoiding_singularity(新路径)
      · roll 0°：plan_ik 通过（肘已弯，几何不再奇异）→ 返回
  → movel 执行抬升
```

对照日志你应能指出：哪一步是弯肘逃逸（movej）、哪一步是抬升（movel）、为什么抬升路径在逃逸日志**之后**才出现。

> **检查题 7.1**：起点 \(q_4=2^\circ\)、目标抬升路径某点也会到 \(q_4=5^\circ\)。先弯肘逃逸还是先 roll？
>
> **答**：先弯肘逃逸（起点在带内，roll 救不了几何伸直）。逃逸把肘弯到 14° 并移动 TCP 后，再从新姿态 build_path，通常抬升路径也随之离开奇异带；剩余的分支/限位类问题才用 roll。
>
> **检查题 7.2**：为什么 `escape_j4_singularity` 用 `movej` 而不是 `movel`？
>
> **答**：`movel` 是笛卡尔直线，要经过接近奇异的雅可比求逆，关节速度会爆炸；`movej` 直接给关节角、不求逆雅可比，穿越/离开奇异带对纯关节运动是安全的。

## 8. 综合误区表

| 误区 | 为什么诱人 | 正确认识 |
| --- | --- | --- |
| YOLO 检测到瓶子就能开始 movel | 检测框看起来"知道瓶子在哪" | 还缺可靠深度、基座变换、多帧共识、可达性、碰撞、围栏检查 |
| 抓取点用所有深度的平均值 | 平均"最公平" | 平均被飞点/背景带偏；要中位数 + MAD + 多帧共识 |
| MoveIt 规划成功 = 可以执行 | 规划器没报错 | 只代表模型内候选存在，缺围栏语义、缺实时环境、缺整臂后验+TCP双复核 |
| 电子围栏能替代 MoveIt 碰撞 | 都叫"安全检查" | 围栏只查 TCP 点，不知整臂形状；两者盲点互补 |
| 奇异了就把 8° 阈值改小 | "阈值挡了我就放宽阈值" | 阈值不修复几何不可达，只是允许更靠近病态区；先查观察位/目标/底盘 |
| 绕工具轴 roll 能解决所有奇异 | roll 确实解决过一些奇异 | roll 不移动腕心，救不了几何伸直的肘；起点在带内要弯肘逃逸 |
| 逃逸后沿用原来算好的抬升路径 | 路径已经算好了，省事 | 弯肘改变了 TCP，必须从新姿态重建路径（这就是 build_path 回调的原因） |
| 出错了让机械臂自动退回 | 退回"更安全" | 未知错误时不能信任周围空间，退回引入新的未验证运动；应停住保持 + 人工处置 |

**I3.** 解释为什么 `SafeMotionPlanner` 既要电子围栏 TCP 复核、又要 MoveIt 后验碰撞复核。各自盲点是什么？

**C1.（诊断）** 日志显示：8 个观察位候选、16 次尝试全部被"围栏拒绝：TCP 比垫大后的盒子还深入 1.5 cm"打回。把阈值调宽是对的吗？真正根因是什么？怎么修？

**C2.（迁移）** 2 连杆机械臂 \(l_1=l_2=0.3\)。当 \(\theta_2=5^\circ\) 时 \(\det\mathbf J\) 是多少？这个姿态"离奇异有多近"？如果任务要求末端沿"手臂伸直方向"以 0.1 m/s 移动，直觉上关节速度会怎样？

**C3.（综合）** 机器人已抓瓶，当前 \(q_4=4^\circ\)，要退开 8 cm 再放下。请按 `_plan_local_leg` 的逻辑，写出程序依次会做哪些动作（含哪一步是 movej、哪一步是 movel、build_path 何时被调用）。

---

### 答案与要点

**B1.** \(x_c=\frac{(u-c_x)z}{f_x},\ y_c=\frac{(v-c_y)z}{f_y},\ z_c=z\)。\(f_x\) 是水平焦距（像素单位），\(c_x\) 是主点水平像素坐标（光轴穿过图像的位置）。

**B2.** \(J_4\) 奇异带 8°（进带则拒）；逃逸角 14°（弯肘目标，比带宽 6°）；限位余量 3°（距软限位不足则拒）；通道半径 4.5 cm（圆柱通道）；最小阻挡点 18（可疑点够 18 个才中止）。

**B3.** movej 发七个关节角；movel 发 TCP 位姿（笛卡尔）。

**I1.** 内点是前四个（0.39–0.41），中位数 = 0.40 m；对内点 MAD：偏差 0.00/0.01/0.01/0.00，中位数 ≈ 0.005 m < 0.018，通过。0.95、1.60 被判离群丢弃。

**I2.** \(\mathbf t-\mathbf s=(0,0,0.25)\)，\(\lVert\cdot\rVert^2=0.0625\)。\(a=\frac{0+0+0.10\cdot0.25}{0.0625}=\frac{0.025}{0.0625}=0.4\)（在 0.08–0.86 内）。\(\mathbf c=(0,0,0.10)\)，垂直距离 \(=\lVert(0.03,0,0)\rVert=0.03\,\mathrm m<0.045\) → 是可疑点（够 18 个才中止）。

**I3.** 电子围栏只对 FK 出的 TCP 点检查任务空间边界（工作区/禁入盒/允许区），盲点是不知道手臂每一节的形状；MoveIt 后验对整条密集关节路径做整臂+工具几何碰撞，盲点是不带项目的允许区语义。两者盲点互补，缺一会漏（围栏漏整臂碰撞，MoveIt 漏越界飞出允许走廊）。

**C1.** **调宽阈值是错的**——那只会放行更靠禁区的路径。真正根因是 OMPL 的 `longest_valid_segment_fraction` 默认 0.01 太粗，边碰撞检测两次采样间关节走好几度、TCP 平移近 10 cm，规划器"没检测到"路径已进禁区，而独立围栏用更密插值发现了。修法：把 lvsf 收紧到 0.0025（每段约 1.8°，与复核的 1.5° 同量级），让规划和复核的判定密度一致（正是 `ompl_config.py` 的做法）。

**C2.** \(\det\mathbf J=l_1l_2\sin\theta_2=0.3\times0.3\times\sin5^\circ=0.09\times0.0872\approx0.00785\)。相比 \(\theta_2=90^\circ\) 时的 0.09，只有约 8.7%——**已经很接近奇异**。沿"手臂伸直方向"移动正是那个塌缩的方向，要 0.1 m/s 需要极大甚至发散的关节速度（按 \(1/\sigma_{\min}\) 放大）。

**C3.** 
1. `_plan_local_leg("退开", build_retreat_path, ...)` 先调 `escape_j4_singularity`：\(|4°|<8°\)，需逃逸。
2. 优先 +1 方向 → target \(q_4=+14°\)，检查限位余量 ✓，把 4°→14° 按 1.5° 插密（约 7 点），每点 FK→TCP→逐点围栏 ✓。
3. **movej** 执行弯肘（TCP 已改变），stage("J4 奇异带弯肘逃逸")，返回 escaped。
4. **现在**才调 `build_retreat_path()`——从逃逸后的新 TCP 构建退开 8 cm 的直线位姿序列。
5. `_plan_ik_avoiding_singularity` 对这条新路径做 roll 重试（通常 0° 就过，因肘已弯离带）。
6. **movel** 执行退开。之后才是放下动作。

## 12. 继续读代码的最短路线

把上述概念逐行落回代码，按此顺序读，每读一个函数都问三个问题：**它接收的坐标是哪个系？它输出的是测量、候选、批准动作、还是实际执行？它失败后会继续、换候选、还是安全中止？**

```
perception.py                                  (第2章 抓取点估计)
  → core.py 的 Localization / 插值 / look_at_camera_pose
  → demo.py::localize
  → safety.py                                  (第5章 电子围栏)
  → safe_planner.py                            (第3章 审批链)
  → planner.py + ompl_config.py                (第3章 采样密度)
  → demo.py::candidate_path / _approach_pregrasp / _plan_local_leg
  → robot.py::plan_ik / escape_j4_singularity  (第4、6、7章 控制与奇异)
        / move_linear / execute_planned_joints
  → collision.py                               (第5章 圆柱通道)
  → table_model.py + scene.py                  (第5章 桌面拟合与体素)
```

能对每个函数稳定回答那三个问题，你就真正读懂了本项目最关键的五个部分——不只是"知道它拒了"，而是"知道它为什么拒、以及正确的修法是几何/标定/底盘，而不是放宽阈值"。
